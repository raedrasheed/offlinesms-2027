# Composer: emoji, stickers and polls

Screenshots (English and Arabic/RTL) are in [`docs/screenshots/composer/`](screenshots/composer/). They were taken from the web feature gallery described in §5.

## 1. Emoji picker

- **Where:** the smiley button in the composer opens an inline panel in place of the keyboard. The panel takes the last keyboard height, so the conversation doesn't jump. The keyboard button switches back, and focusing the text field closes the panel.
- **Content:**
  - Search.
  - **Recently used** (per user, on the device only).
  - The existing **Animated** 3D set.
  - Nine Unicode categories: 1,906 base emoji. Skin-tone variants are not included.
- **Device compatibility:** emoji newer than the device's system emoji font are hidden, so no empty boxes appear. The cut-off comes from the Android API level or iOS version (`maxEmojiVersionFor`). For example, Android 11 shows up to Emoji 13.0 and Android 14 up to 15.0.
- **Search** matches **English and Arabic** keywords whatever the UI language. Arabic spelling variants are folded: أ/إ/آ→ا, ى→ي, ة→ه, and harakat and tatweel are ignored. Flags can be found by country name in either language.
- **Insertion:** at the caret, replacing any selection.
- **RTL:** layout, search field alignment and category order follow the language.
- **Size / speed:**
  - Category data: 17 KB of source.
  - Keyword table: 209 KB of source (65 KB gzipped). It is required and parsed **only on the first search**.
  - The grid is virtualized with fixed-height rows, so only visible rows mount.
- **Data:** generated by `apps/mobile/scripts/build-emoji-data.mjs` from emojibase-data 16.0.3 (MIT) and Unicode CLDR 46 (Unicode License v3). See `apps/mobile/THIRD_PARTY_NOTICES.md`.

## 2. Stickers

- **Pack:** "Simsim" has 16 stickers: 12 expressions plus bilingual text stickers (شكراً, مرحبا, Thanks!, OK!).
  - It is **original artwork** authored for this project as SVG and released under **CC0 1.0** (`assets/stickers/simsim/LICENSE.md`).
  - It is rendered to 384 px transparent WebP by `scripts/stickers/build-stickers.mjs`: 209 KB in total, about 13 KB each.
- **Composer:** the Stickers tab has a recently used section and the pack. A tap sends the sticker; a long press opens a large preview with a Send button.
- **Message:** `type: 'sticker'` with `sticker: {packId, stickerId, alt}`.
  - The server accepts only ids in its catalog (`functions/src/chats/stickerCatalog.ts`), so a client cannot inject an image URL. A test keeps the catalog identical to the app's `pack.json`.
  - `text` is set to the sticker's emoji. Older app versions therefore show 👋, or even the animated big emoji, instead of an empty bubble.
- **Rendering:** chromeless on the wallpaper. A sticker from a pack this app version doesn't have shows its emoji instead.
- **Caching and loading:** images ship with the app and are resolved by Metro, so the recipient renders a sticker **without any network request**. A slow network only delays the message itself, which is a few hundred bytes. React Native decodes an image only when a cell or bubble is on screen. The Stickers tab mounts on first open.
  - **Not built:** downloadable packs. They would need hosting, which is a deployment decision.

## 3. Polls

- **Create:** Attach → Poll. Enter a question (≤ 300 characters) and 2–12 unique options (≤ 100 characters each), and choose **single** or **multiple** choice. The form applies the same rules as the server.
- **Message:** `type: 'poll'` with
  - `poll: {question, options[{id,text}], multiple, closed, votes{uid: optionIds}, counts, voterCount}`.
  - `text` is `📊 question`, which older clients, the chat list and push notifications show.
- **Server rules (`functions/src/chats`):**
  - Creating a poll goes through `sendTextMessage` with `kind: 'poll'`. It gets the same membership, locked-group, admins-only, block and `localId` idempotency gates as text.
  - `votePoll` runs in **one transaction**. It re-checks that the caller is a participant and an **active member**, refuses disabled conversations, blocked direct chats, closed polls, non-polls and unknown options, and allows at most one option in single choice. An empty selection retracts the vote.
  - **No double counting:** counts are **recomputed from the per-voter map** on every vote and never incremented. A duplicated or retried request therefore changes nothing.
  - **No stale overwrite:** each vote carries a strictly increasing `seq`. The last `seq` per voter is kept in a server-only doc (`…/messages/{m}/pollVoters/{uid}`), and the rules give clients no access to message subcollections. A late retry of an older vote is acknowledged as `stale` and ignored.
  - `closePoll` is limited to the creator. Results stay visible after closing.
  - Delete-for-everyone removes the poll, including its votes, and stickers.
- **Client:**
  - Votes are optimistic. They are written to the local `payload_json` immediately and queued in the outbox, which is ordered and idempotent per `seq`.
  - Live results arrive from the conversation's realtime feed. Only the poll's bubble re-renders, because of structural sharing.
  - Local DB v7 adds `messages.payload_json`.
- **Visibility:** votes are not anonymous. Members can see who chose what, as in common messengers. The bubble shows counts per option and the number of people who voted.

**Not validated here:**
- Rendering on physical Android and iOS devices: emoji font coverage per OS version, WebP stickers on iOS, keyboard ↔ panel height on real keyboards.
- Two real devices exchanging stickers and polls over a throttled network.
- Connection recovery is covered by the outbox and feeder tests, not by a device run.

## 5. Feature gallery (testable web build)

```
cd apps/mobile
npm install --no-save @expo/metro-runtime@~5.0.5   # web runtime, not an app dependency
EXPO_PUBLIC_FEATURE_GALLERY=1 npx expo export -p web --output-dir dist-gallery
npx serve dist-gallery   # then open /#chat, #emoji, #emoji-search, #stickers, #create-poll, #sync
```

- The gallery renders the **real components** with sample data. It uses no Firebase and no local DB.
- The language follows the browser (en or ar).
- `index.js` includes the gallery only when the variable is `1`. The variable is inlined at build time and the dead branch is folded, so app builds never contain it (verified: the gallery bundle contains no app screens).

## 6. Compatibility with an older server

- **Deploy the functions before releasing the app.**
- If the app is released first:
  - A sticker or poll sent through the local-first outbox reaches an old `sendTextMessage` as **plain text**: the sticker's emoji, or "📊 question". The old server ignores `kind`, and the outbox sends the fallback text.
  - On the legacy direct path, the same send is refused with `text-required`.
  - Votes fail, because `votePoll` doesn't exist on the old server. The queued vote is dead-lettered after its retries, and the next snapshot restores the real tally.
