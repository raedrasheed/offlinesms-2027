# مقاطع — OfflineSMS 2.5.0 / build 31

تنفيذ ميزة الفيديو القصير وفق نموذج المشاهدة والملف الشخصي المعتمد. يستبدل تبويب «المكالمات» بتبويب «مقاطع»، مع الإبقاء على مسار استقبال المكالمة الموجود. هذا المستند يصف الكود وتجهيز النشر؛ لا يعني أن الخدمة نُشرت على Firebase أو أن نسخة متجر موقّعة بُنيت.

## ما يقدمه الإصدار

- موجز عمودي «لك / أتابعهم»، بحث في الوصف والوسوم والناشر، إعجاب، حفظ، متابعة، تعليق وردود وإعجابات التعليقات، إبلاغ وحظر و«غير مهتم».
- ملف ناشر يتضمن الصورة والاسم والمعرّف والنبذة والإحصاءات وشبكة الأغلفة؛ إدارة طلبات المتابعة وإزالة المتابعين للحسابات الخاصة. رقم الهاتف لا يدخل بيانات ملف المقاطع.
- تسجيل بالكاميرا أو اختيار فيديو، قص البداية والنهاية، كتم الصوت، إضافة نص، اختيار لحظة الغلاف، وصف ووسوم، اختيار الجمهور، التحكم بالتعليقات والتنزيل.
- مسودات محلية منفصلة لكل حساب؛ نسخ الملف من ذاكرة المنتقي المؤقتة إلى مجلد دائم قبل حفظ المسودة. تقدم الرفع وإيقافه واستئنافه وإلغاؤه وإعادة المحاولة. الاستئناف بعد إغلاق التطبيق يبدأ رفع المصدر مجددًا بنفس مرجع المسودة، ولا يدّعي استئناف البايتات من جلسة رفع سابقة.
- معالجة فعلية على الخادم إلى MP4/H.264/AAC بقياسي عرض يصلان إلى 720 و360 بكسل، مع الحفاظ على النسبة، واستخراج JPEG للغلاف. جهاز واحد يشغّل مقطعًا واحدًا في الواجهة الأمامية؛ إيقاف/تفريغ المشغل عند مغادرة الشاشة أو انتقال التطبيق إلى الخلفية.
- مشاركة إلى المحادثات والمجموعات برسالة من النوع `clip`. تُخزّن الرسالة معرّف المقطع فقط ومعاينة عامة، ويُتحقق من الوصول عند فتحها. تحويل الرسالة يمر عبر نفس خدمة المشاركة؛ لا تُنسخ روابط المشاهدة الخاصة أو بيانات الناشر إلى سجل الرسائل.
- روابط المشاركة الخارجية تستخدم `https://links.offlinesms.com/clips/{id}` على نطاق روابط التطبيق. يستقبل التطبيق أيضًا `offlinesms://clips/{id}` وروابط `offlinesms.com/clips/{id}`، ويستأنف فتحها بعد تسجيل الدخول. صفحة ويب عامة لا تكشف المحتوى الخاص.
- لوحة `/admin/clips` للمشرف العام: مراجعة المحتوى، الموافقة/الرفض/الإزالة مع السبب وسجل تدقيق، مراجعة البلاغات والتعليقات، تقييد حساب في المقاطع، وحدود الخدمة وإحصاءات المشاهدة والتخزين المسجّل.

## الجمهور والخصوصية

| الخيار | من يستطيع المشاهدة |
| --- | --- |
| عام | مستخدم مسجل ونشط، بعد نشر المقطع وموافقته؛ الحساب الخاص يضيف شرط المتابعة المقبولة |
| المتابعون | المتابعون المقبولون فقط |
| مجموعة | الأعضاء الحاليون الفعّالون في المجموعة؛ الحساب الخاص يضيف شرط المتابعة المقبولة |
| أنا فقط | صاحب المقطع فقط |

الحظر في أي اتجاه يمنع المشاهدة والتفاعل. زوال عضوية المجموعة أو قبول المتابعة يؤثر على طلبات الوصول التالية. يستطيع مشرف المنصة المعتمد فحص المحتوى لأغراض المراجعة؛ صلاحية مشرف المؤسسة لا تعطيه هذه السلطة.

بيانات المقاطع تُقرأ عبر الخدمات الموثقة، ولا توجد قراءة مباشرة لمجموعات Firestore الخاصة بها. ملفات المخرجات لا تستخدم رموز تنزيل Firebase الدائمة. روابط المشاهدة الموقعة صالحة لمدة لا تتجاوز 120 ثانية؛ لا يمكن سحب نسخة حفظها المستخدم أو إبطال رابط صادر قبل انتهاء مدته بمجرد تغيير الجمهور. يُراجع التطبيق الصلاحية عند طلب رابط جديد وعند العودة إلى الشاشة.

قد ينشئ SDK رمز تنزيل مؤقتًا للمصدر الذي رفعه صاحبه. مشغلات التخزين تمسحه، وتفشل عملية الإرسال للمعالجة إن تعذّر مسحه من جيل المصدر المحدد؛ تُحذف النسخة الأصلية بعد نجاح المعالجة. توجد نافذة بين الرفع والمشغّل، ولا يعرض التطبيق رابط الأصل. تفاصيل هذا الحد وحدود محاكي التخزين في [CLIPS_SECURITY.md](CLIPS_SECURITY.md).

حذف الحساب يضع حاجز حذف دائمًا قبل حذف المصادقة، ثم ينفذ مهمة قابلة لإعادة المحاولة لتنظيف المقاطع والعلاقات والتفاعلات والبيانات الشخصية. تتحقق المعاملات من هذا الحاجز حتى لا تُعيد عملية قديمة إنشاء بيانات بعد التنظيف. تُحذف مسودات الحساب من هذا الجهاز بعد نجاح الحذف؛ تسجيل الخروج وحده يبقيها معزولة لنفس الحساب.

## الإعدادات الافتراضية

| إعداد `systemSettings/clips` | الافتراضي |
| --- | --- |
| `enabled` | `false` |
| `moderationRequired` | `true` |
| `maxDurationSeconds` | `60` |
| `maxUploadMB` | `80` |
| `maxDailyUploads` | `10` |
| `termsVersion` | `clips-v1` |
| `supportEmail` | بريد الدعم المضبوط في لوحة الإدارة |

التفعيل متاح من لوحة الإدارة بعد توفير بريد دعم. مراجعة المحتوى بشرية؛ لا يوجد في هذا الإصدار ادعاء بفحص آلي لكل محتوى الفيديو. ترتيب «لك» يجمع الحداثة والتفاعل داخل نافذة محدودة ثابتة الصفحات، وليس نموذج توصية بالتعلم الآلي. البحث يجتاز الصفحات ويعرض إمكانية متابعة البحث؛ لا يدعي فهرسة نصية شاملة فورية.

## النشر

1. تنفيذ `npm ci` من الجذر و`npm --prefix apps/mobile ci` للتطبيق، ثم بناء Functions ولوحة الإدارة. راجع [CLIPS_MEDIA.md](CLIPS_MEDIA.md) لتثبيت FFmpeg/ffprobe 8.1.3 الموثق ببصمة SHA-256 ومتطلبات Linux x64 قبل النشر؛ ملفات التنفيذ خاصة بالخادم وليست ضمن تطبيق الهاتف.
2. نشر `firestore:rules,firestore:indexes,storage` وانتظار جاهزية الفهارس الجديدة. لا تمنح قراءة عامة لـ `clipMedia` أو `clipUploads` على مستوى Cloud Storage IAM.
3. نشر المجموعة الجديدة `clips` من `scripts/release/function-groups.json`، وإعادة نشر `deleteMyAccount` و`onMessageCreate` و`onMessageCreateNotify` لتكامل الحذف والمعاينات. مثال من جذر المستودع:

   ```bash
   npx firebase deploy --project offlinesms-prod-2027 --only firestore:rules,firestore:indexes,storage
   npx firebase deploy --project offlinesms-prod-2027 --only "$(node scripts/release/deploy-only.mjs clips)"
   npx firebase deploy --project offlinesms-prod-2027 --only functions:deleteMyAccount,functions:onMessageCreate,functions:onMessageCreateNotify
   ```

4. التأكد من صلاحية حساب خدمة التشغيل لتوقيع روابط Cloud Storage (`iam.serviceAccounts.signBlob`) وصلاحيات قراءة/كتابة/حذف ملفات الدلو المطلوبة، ومن نشر مشغلات Firestore وStorage والجدولة وحذف Auth. عمليات المعالجة تستخدم إعدادات ذاكرة/مهلة/تزامن محدودة في المصدر.
5. نشر لوحة Next.js الحالية مع بيانات Firebase Admin المعتادة، ثم نشر موقع روابط التطبيق. الهدف `website` يحتاج ربطًا بموقع Firebase Hosting الفعلي؛ لا يوجد معرّف موقع مخمّن في هذا الإصدار.
6. استبدال `TEAMID` الموجود أصلًا في `apps/website/.well-known/apple-app-site-association` بمعرّف فريق Apple الصحيح قبل ادعاء عمل Universal Links على iOS. التحقق من بصمة Google Play App Signing في `assetlinks.json`. أضيف مسار `/clips/` في إعداد Expo وفي AndroidManifest الأصلي حتى يشمله البناء عبر Gradle.
7. بناء نسخة الهاتف 2.5.0، رقم البناء 31، وإجراء فحص جهاز فعلي قبل نشر المتجر. يمكن استخدام سير العمل الحالي `Production Android release`؛ يحتاج أسرار توقيع الإنتاج وإعدادات Firebase الصحيحة، ولا ينشر إلى المتجر تلقائيًا.
8. تشغيل تجربة داخلية بحسابين ومجموعة: رفع مقطع، مراجعته، المشاهدة/الصوت، التفاعلات، مشاركة إلى محادثة، تغيير الجمهور، مغادرة المجموعة، الحظر، إعادة فتح التطبيق أثناء الرفع، حذف المقطع وحذف الحساب. بعد النجاح يُفعّل `enabled` من لوحة المقاطع.

تشمل الاختبارات المنفذة معالجة فيديو حقيقي باستخدام FFmpeg، معاملات Firestore ومحاكي Storage/Auth، قواعد الوصول، دورات حياة مشغل الهاتف، المسودات، التفاعلات، حفظ مراجع المقاطع عبر SQLite، الروابط، وصلاحيات لوحة الإدارة.

جُهز معرض اختبار منفصل يستخدم مكونات الواجهة الفعلية ورسومًا محلية وبيانات اختبار: `EXPO_PUBLIC_CLIPS_GALLERY=1 npx expo export -p web --output-dir dist-clips-gallery`. لا تدخل بيانات المعرض في موجز المستخدمين. تعذّر التقاط صور تشغيلية في هذه البيئة: المتصفح المحلي لا يستطيع إنشاء مقبس تشغيله، والمتصفح السحابي لا يصل إلى خادم المعاينة المحلي. لذلك لا تُعد صور النموذج المعتمد إثباتًا لفحص جهاز فعلي.

بيئة العمل لا تحتوي حساب Firebase CLI مسجلًا (`firebase login:list` يعيد عدم وجود حسابات)، ولم تُستخدم مفاتيح توقيع إنتاج. نجاح TypeScript وبناء JavaScript لـ Android/iOS لا يعادل بناء AAB/APK موقّع أو اختبار الكاميرا على هاتف.
